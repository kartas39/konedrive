- **F198. The order of the tree lock and the lifecycle lock is kept by hand** — the tree lock
  comes before the lifecycle lock (the write design §9), and nothing in the types says so: a new
  caller that takes the lifecycle lock and then waits for the tree lock brings back the hang of
  three (a cycle, that caller, and a writer waiting for the lifecycle lock between them). One
  caller does take them the other way round, the change of the mode with its forced drop: it is
  safe only because the folder's sync is stopped then and a third lock (`switching`) keeps the
  forced drop of a running folder out. One test covers the order (`sync::tests::onedrive::
  read_write`, the cycle, the forced switch and the bring-up at once); the exception is argued
  from the code. FRAGILE. Reasoned. Open.

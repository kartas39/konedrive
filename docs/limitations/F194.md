- **F194. What still fails a whole cycle when something is taken off the disk**
  (`konedrived/src/remote/materialize/removal.rs` `take_off`, `remove_whole`; `removal/unplaced.rs` `waits`; issue #104) —
  - an error while the cycle looks at what can no longer be placed (a directory it may not read, an
    I/O error) fails the cycle, and nothing is committed; so does an object of a removed item that
    will not go (F116). Every cycle fails that way until the cause is gone, and nothing else of the
    folder syncs meanwhile. The error is logged, as any failed cycle's is.
  - **Another filesystem mounted inside no longer does.** Inside a folder that can no longer be
    placed it keeps that folder waiting, and the skipped list says so (F188). Inside a folder
    OneDrive removed, the folders above the mount are not touched and their removal waits (the
    base keeps them, as items like any other) until it is unmounted; what can go of the removed
    folder goes, and the rest of the account folder syncs. Nothing in the skipped list says so, since
    the folder is not a skipped item: the mount itself is listed under Not Uploaded as on another
    device, and the journal names it. While it waits, every poll runs a cycle. Before, its mount
    point failed every cycle until it was unmounted.

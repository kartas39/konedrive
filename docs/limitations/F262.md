- **F262. Taking the marks off a copy waits for the disk twice, with the folder's tree lock held**
  (`konedrived/src/local/examine/classify.rs` `strip`; `konedrive-fs/src/placeholder.rs` `strip`;
  quality finding `UP7`) — a copy that kept an item's marks (`cp -a`, a file manager that copies
  attributes) loses them through the one strip of the code base: the item id, `fsync`, the rest,
  `fsync`. So a crash never leaves an id with no state inside the folder, the one combination the
  helper refuses to open. The price is two `fsync` for each copy, inside the examination, which
  holds the tree lock (`local/watcher/service.rs`): nothing from OneDrive is applied meanwhile.
  Measured once on Btrfs on an NVMe disk, debug build, 3000 downloaded copies of a three-byte
  file in one Full local scan: 6.7 s, against 0.85 s with the strip in listing order and no
  `fsync` (about 2 ms a copy). On a rotating disk it is expected to be an order of magnitude
  more; not measured. A second strip without the `fsync` was not taken: it would be the two
  strips with different guarantees that `UP7` removed. The strips of what has already left the
  folder (`folder/disk.rs` `outside`) and of the reconcile (`remote/materialize/`) are still in
  listing order with no `fsync` (`UP7`, "Left"). LIMIT (chosen) · measured (the time), reasoned
  (the rotating disk). Open.

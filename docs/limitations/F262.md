- **F262. Taking the marks off a copy waits for the disk, with the folder's tree lock held**
  (`konedrived/src/local/examine/classify.rs` `strip`; `konedrive-fs/src/placeholder.rs` `strip`;
  quality finding `UP7`) — a copy that kept an item's marks (`cp -a`, a file manager that copies
  attributes) loses them through the one strip of the code base: the item id, `fsync`, then the
  rest. So a crash never leaves an id with no state inside the folder, the one combination the
  helper refuses to open. The price is one `fsync` for each copy, inside the examination, which
  holds the tree lock for its whole run (`local/watcher/service.rs`): the reconcile (nothing
  from OneDrive is applied), the replacements of downloaded files and the upload worker all
  wait for that lock meanwhile. Measured on Btrfs on an NVMe disk, debug build, 3000 downloaded
  copies of a three-byte file in one Full local scan: 3.8 s, against 0.85 s with the strip in
  listing order and no `fsync` (about 1 ms a copy more). On a rotating disk it is expected to
  be an order of magnitude more; not measured. The strip had a second `fsync` after the rest
  (6.7 s in the same measurement); it is gone for every caller. Once the id is gone and on
  disk the object is an ordinary one, and a crash can leave some of the other marks on it:
  - a copy or a file uploaded again as new, inside the folder (the examination;
    `upload/local.rs` `strip_found`): a directory, or a downloaded file. With no id the helper
    lets it through (a state `hydrated` with no id is allowed, its content is there), and the
    examination takes an entry with no id for new whatever else it carries;
  - what left the folder (`upload/move_out/`: `cases.rs`, `tidy.rs`, `dropped.rs`): stripped
    only once its content is local, and outside the folder nothing is intercepted. A row
    replayed after the crash is refused the object by the helper for having no id (`EPERM`),
    which with the row's marker reads as "stripped": the id alone decides it.
  The reconcile does not call this strip. So the strip is only for an object whose content is
  there; a state "not downloaded" left with no id would not be an ordinary file. A strip
  without any `fsync` was not taken: it would be the two strips with different guarantees that
  `UP7` removed. The strips of what the reconcile rescues or removes (`folder/disk.rs`
  `outside`, `remote/materialize/`) are still in listing order with no `fsync` (`UP7`, "Left").
  LIMIT (chosen) · measured (the time), reasoned (the rotating disk, the callers' crash
  arguments: no crash was made). Open.

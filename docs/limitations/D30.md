- **D30. The structure guard reads lines, not Rust.** DEBT, *reasoned*, open.
  `scripts/check-structure.sh` checks the size limits, that no source file holds tests, and
  the order of the daemon's layers (`CONTRIBUTING.md`, "The structure of the code") with
  patterns over the text of the tracked files. What it does not see:
  - **Layers.** Only a path written as `crate::<directory>` counts (and `super::<directory>`
    in a directory's own `mod.rs`). A higher layer's item reached through a re-export of a
    permitted directory, through a `use … as` name or through a path a macro builds passes.
    Rules 4 and 5 (one D-Bus interface in one file, every `impl SyncService` in `sync/`) are
    not checked at all.
  - **Test code.** It is told by name and by declaration: a `tests` directory, `tests.rs`,
    and a module declared right under `#[cfg(test)]`, with everything below it. Such a
    module is exempt from the layer order and has a test file's size limit, but no test may
    be in it. A module behind another condition (`#[cfg(any(test, feature = "…"))]`) is
    taken for source. A single `#[cfg(test)]` function or constant in a source file is held
    to the layer order like the code around it, though rule 3 exempts it.
  - **Tests outside `tests.rs` and `tests/`.** Found by `#[test]`, `#[tokio::test]` and a
    `#[cfg(test)] mod … {` at the start of a line; a test attribute a macro writes is not.
  - **Size.** Only `.rs`, `.cpp`, `.h`, `.qml`, `.sh`, `.py` and `.md` files are counted.
  - `docs/code-map.md` is kept by hand: nothing checks that every file has its line there.

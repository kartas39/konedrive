- **D58. The rule for locks is not asked of the helper or of test doubles.**
  DEBT, *reasoned*, open.
  - Rule 7 of `CONTRIBUTING.md` (a lock of `std::sync` is taken through `panic::lock`, `read` or
    `write`) is checked by `scripts/check-structure.sh` for every source file but these:
    - `crates/konedrive-helper/`: it has its own `lock` (`shared.rs`) and writes the recovery out
      at five more places (three in `outbox.rs`, two of them a `Condvar`'s wait; `pool.rs`;
      `shared/daemons.rs`). Code that runs as root is not changed for tidiness.
    - Files named `testing.rs` or under `testing/`: test doubles, which keep `unwrap` like the
      tests do. `scripts/check-structure.sh` takes most of them for source otherwise (`D30`).
  - The files that hold the one function are left out whole (`konedrived/src/panic.rs`,
    `konedrive-graph/src/lib.rs`, `konedrive-tree/src/outbox/changes.rs`): a second lock
    written there with `unwrap` passes. The other crates (`konedrivectl`, `konedrive-dbus`,
    `konedrive-fs`, `tests/write-account`) are checked and have no such function, and no lock
    of `std::sync` in source today; the first one there needs a function of its own and a
    line in the guard.
  - What the guard finds: `.lock()`, `.read()` or `.write()` with nothing passed, or
    `Mutex::lock(…)` and the like, followed in the same chain (on the line, or on the next
    line that is not empty or a comment) by `unwrap…`, `expect`, `ok`, `map_err`, `is_ok` or
    `is_err`.
  - What it does not see: a lock result kept in a variable and looked at later, `match` or
    `if let Ok(…) = ….lock()`, `try_lock`, a `Condvar`'s wait, a result handed to a function
    or returned with `?`, a lock taken through another path (`LockResult` from a function of
    our own, a `use … as` name), and a chain whose next call is two or more code lines away.
  - What it finds wrongly: any other `.read()` or `.write()` that takes nothing and whose
    result is unwrapped (none in the code today; `std::io` and tokio's take an argument or
    are awaited).
  - `konedrive-graph` and `konedrive-tree` have one function each of their own
    (`konedrive-graph/src/lib.rs` `lock`, `konedrive-tree/src/outbox/changes.rs` `dirty`): no
    crate below the daemon holds such a thing for all three.

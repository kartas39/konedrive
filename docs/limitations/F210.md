- **F210. An entry the examination cannot open, strip or read is passed over, and the user is not
  told which** (`local/examine/run.rs` `entry_io`, `local/watcher/mod.rs` `FAILING_AFTER`;
  quality findings `LO3` and `LO13`) — one entry's trouble no longer fails the batch. Gone since
  it was listed, the entry is skipped. Anything else (a file of ours owned by another user, an
  immutable copy that kept its attributes, a read error) passes it over: nothing at its place
  counts as missing, it gets no row, and a copy that could not be stripped is not uploaded as
  new, nor is anything new inside a directory that could not be. What follows:
  - A passed-over entry is examined again every `RECHECK` (30 s) for as long as its cause lasts,
    with a warning in the log each time. Nothing else says so: `Examined::unreadable` is read by
    nothing but tests, the entry is not in Not Uploaded, and `LastError` does not mention it. A
    file the user edited and the daemon cannot open is not uploaded, in silence.
  - An item of OneDrive moved here into a directory that could not be stripped gets its `move`
    row with no folder to go into; what the worker does with such a row was not traced.
  - A failure that is not one entry's (the store, the root) still fails the batch, which is
    offered again with a backoff. `LastError` says so from the third failure in a row
    (`FAILING_AFTER`, chosen, not measured: some 15 s at the default clocks) until a batch
    passes.
  - A filesystem that holds no user attributes (vfat, some FUSE mounts) answers `EOPNOTSUPP`
    to a read of one: read as "no attribute" wherever an attribute is read by name
    (`folder/disk.rs` `attr_by_name`: the examination's entries and `Disk::probe`, which the
    reconcile's scan uses too). Such a mount inside the folder is then what any other mount is
    (F72). An attribute read through an open descriptor (`placeholder::read_state`,
    `read_item_id`) still answers the error; whether anything reads one on such a mount was not
    traced.

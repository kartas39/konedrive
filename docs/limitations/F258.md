- **F258. The outbox worker writes every file's upload mark again when it starts**
  (`konedrived/src/upload/engine/marks.rs:134` `mark_rows`, `upload/local.rs:388` `mark`) — the
  worker keeps in memory which rows it marked (`user.konedrive.sync` on the file), and its first
  pass after a start sets the mark of every row without reading what is there: a file that waits
  (a blocked new file, say) gets the same attribute written again and its change time moves,
  with nothing changed. Once per start of the worker in the daemon; in the tests' fixture
  (`remote/testing.rs` `World::upload`), which makes a new worker at every call, at every call —
  which is why the tests that assert "no object is touched in a cycle with nothing new" compare
  the change time only of objects that carry an item id. Not in the files of `B4-6`; found while
  the scenarios of pull request #178 were run on `dev` too. DEBT · measured (a probe that printed
  the change time after the cycle, the examination and the worker: only the worker moved it) · open.

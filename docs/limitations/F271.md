- **F271. A folder's lock on its directories' modes is found through a table, and two callers take it by hand** (`folder/disk.rs`,
  `Modes`, `FOLDERS`; quality finding `HY9`) — the one process-wide `DIR_MODES`, re-entrant by a
  thread-local count, is gone: each sync folder has its own lock, not re-entrant, and what
  nests windows takes it once and hands the hold on (`Disk::window`). What is left of the old
  shape:
  - **The lock is found, not owned.** A `Disk` is opened anew for every use (about forty
    places), so the lock cannot live in one; `Modes::of` looks it up in a process-wide table
    by the device and inode of the root directory, and an entry goes when nobody holds a
    share. A root directory replaced by another (removed and made again) gets another lock,
    while a `Disk` opened on the old one keeps the old: the two then do not exclude each
    other. Nothing in the daemon swaps a registered root's directory.
  - **Outside `Disk` the lock is still taken by convention**: a pin written on a folder
    (`hydration::pin::set_pin`, which is handed the lock by `sync/pins.rs`), and the drive
    written on or taken off the root (`folder/root.rs`, `mark_drive`, `forget_drive`). A new
    place that lifts a directory's write bit and does not take it compiles.
  - **The whole-tree walks hold it throughout** (`lock_tree`, `unlock_tree`), as before; now
    only that folder's windows wait for them, not every account's.

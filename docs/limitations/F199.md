- **F199. A folder without interception has its path, and nothing else, while the daemon starts**
  (`sync/resume.rs` `restore_locked`; found in the review of the fix for quality finding `CL2`'s
  neighbour). FRAGILE, *reasoned* (traced in the code, not observed), open.
  The daemon claims its bus name and only then brings the folders up, one account after
  another (`daemon/startup.rs`, `serve` then `resume_all`). A folder registered without
  interception has no registration until its turn comes. Since the fix it is published by its
  path from the start, so that `konedrivectl` can tell it from an account with no folder; its
  `State` is `none` until it is brought up. It concerns only folders registered without
  interception: an intercepted one is held, with its registration, before the name is claimed.
  The window lasts from the name being claimed until `resume` has brought up the accounts
  before this one and this one; how long that is was not measured. In it:
  - **The path commands are refused with an untrue sentence.** `sync hydrate`, `dehydrate`,
    `pin`, `unpin`, `free` and `open` on a file in that folder are answered `OutsideRoot`: the
    daemon finds the account by the registration (`daemon/manager.rs` `route`), and there is
    none yet. `konedrivectl` finds the folder by its path (`konedrivectl/src/daemon.rs`
    `folders`, `commands/sync.rs` `explained_paths`, `text/refusals.rs`), so it says
    "<path> is not a regular file inside the sync folder (<root>)…", which is untrue for a
    regular file inside it. Before the fix it said "no sync folder is registered", untrue as
    well. The same command a moment later works.
  - **The window's status page shows the path over "No OneDrive folder yet".** The page's
    title is the folder's path whenever there is one (`app/qml/StatusPage.qml`), and the
    state `none` reads as no folder (`app/accountstatus.cpp`), until `State` changes.
  - **`Path` does not change when the folder is brought up**, so no `PropertiesChanged`
    carries it then; a client that waited for `Path` to learn that the folder is up must
    watch `State`.
  - `konedrivectl sync status` prints `Folder:` and `State: none` for it, without the size
    and the count of pins, which nothing has measured yet.

- **F199. A folder without interception is recorded and not up while the daemon starts**
  (`sync/bring_up.rs` `restore_in`, `resume`). FRAGILE, *reasoned* (traced in the code) and measured
  for the state and the refused registration
  (`sync::tests::registration::a_folder_not_brought_up_yet_reads_waiting_under_its_path`), open.
  The daemon claims its bus name and only then brings the folders up, one account after
  another (`daemon/startup.rs`, `serve` then `resume_all`). A folder registered without
  interception is the daemon's from the start, as an intercepted one is: recorded, down, published
  under its path with `State` `waiting`, until its turn comes. The window lasts from the name being
  claimed until `resume` has brought up the accounts before this one and this one; how long that
  is was not measured. In it:
  - **The path commands find the folder and act on a folder that is not up.** `sync hydrate` of a
    file in a folder filled from a directory answers `NoSource` (the directory is not remembered
    across a restart anyway); `dehydrate`, `pin`, `unpin` and `free` work as on a folder that is up.
  - **A registration is refused `AlreadyRegistered`, and a Forget takes the folder away.** Before
    the state was a type the folder had no registration in that window, so a registration of
    another folder was accepted and replaced the record, and a Forget answered that there was
    nothing to forget.
  - **The window's status page shows "Starting…"** under the folder's path, and
    `konedrivectl sync status` prints `State: waiting`, without the size and the count of pins,
    which nothing has measured yet.
  - **`Path` does not change when the folder is brought up**, so no `PropertiesChanged`
    carries it then; a client that waits to learn that the folder is up watches `State`.
  - **A bring-up that fails leaves the folder recorded and down**, `State` `error`, with why in
    `LastError`; it is tried again at the helper's next connect and at the next start.

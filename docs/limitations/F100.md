- **F100. The pause is the tree store's** (`konedrived/src/sync/pause.rs`, `conditions::running::user_pause`; write
  design §11) — `Pause`/`Resume` write `meta.paused_until` in the account's tree store, not
  `config.toml`: a store that is rebuilt (an unknown version, corruption) forgets the pause, and a
  folder with no store — a local one, or a OneDrive folder that is not up or whose sync has not
  started — cannot be paused (`Unsupported`, `NotUp`, which says why). While paused, the poll asks OneDrive for nothing, and the first
  cycle after a restart waits too; `Refresh()` asks for nothing either. A cycle already running when
  the pause comes starts no replacement (the next cycle after the pause is Full and finds them
  again). An upload stops after the fragment it is sending, or before its first one if its session is only being opened (at most 10 MiB, so
  "Uploading now" and `sync transfers` empty within one fragment's time), its session and offset
  kept in the row, which waits as `paused` — no failure, no activity event — through a restart too;
  `UploadQueue.Changes()` lists every row that waits, retries or runs as `paused` while the account is (#19). On
  resume the kept session goes on from its offset; a session OneDrive let expire during a long
  pause starts over from zero, which is logged, and what was sent before is sent again. A
  fragment being sent (the only one of a file up to 10 MiB included) or a metadata request already
  sent finishes. The one stop point before each fragment, the first too (`stop_between_fragments`
  in `upload/content/session.rs`), serves the pause and the write gate (F239). A timed pause is looked
  at by the wall clock at least every minute, so a suspend does not stretch it, and a shorter pause
  set over a longer one ends at its own time (`PauseClock`); the
  pause is worked out and shown by one caller at a time, so a `Pause` or `Resume` that lands as
  the timer ends the pause before it is what the bus shows; a forgotten folder is no longer
  paused. The account has one clock (`conditions::running::Clock`, given in the service's
  `Wiring`): the timer, the keeper of the pause (`user_pause`), the poll and the outbox worker's
  pause check all read it, so a pause that is over for one is over for all, and the whole path is
  tested on a clock moved by hand. The tree store keeps only the time the pause ends and
  compares it with no clock of its own. The worker's other times (a retry, a throttle, an upload
  session's age, the stamp of an activity event) and `LastChecked` are still the system's clock,
  read where they are used: a test that moves the account's clock does not move those.
  The tray's "pause every account" is one `Pause` per account (A23).

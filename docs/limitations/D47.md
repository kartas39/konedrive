- **D47. The registry lists the accounts' folders weakly, and the test support writes it too.**
  DEBT · reasoned (part 5 of `B5`, quality finding `SY8`). The helper's link (`helper/hub.rs`,
  `HelperHub`) and the list of the accounts' folders (`sync/registry.rs`, `Registry`) are two
  objects. The list has one writer in the daemon: the account manager, which adds a folder in the
  lines that add its account to its own list and removes it where it removes the account
  (`daemon/manager.rs`, `list` and `unlist`). What the types still do not say:
  - **The entries are weak references.** The design asked for strong ones. A service holds the
    registry (it asks it for the overlap check, the claims and every account's folders), so
    strong entries would be a cycle that only a `remove` breaks: the manager makes one, but a
    test that drops a service, to restart it or to see its tasks end, does not. So an entry
    whose service is gone is passed over, and taken out when the same account is added again.
  - **The test support is a second writer** (`sync::testing`, `Builder::build`): it adds the
    service it makes, standing in for the manager. A `SyncService` made by `SyncService::new`
    alone is no one's: it is not routed to, not resumed when the helper connects, and not told
    the hold's settings.
  - **The hub knows whom it serves by a weak reference to a trait** (`helper::hub::Served`, which
    the registry implements), because the registry holds the hub. A supervisor whose registry is
    gone ends.
  - **Every account is told the hold's settings and the machine's conditions with the list's lock
    held** (`Registry::tell`), so that two changes arrive in their order and an account added
    meanwhile misses neither. What an account does when told (`SyncService::hold_by`) must
    therefore never ask the registry for anything; a debug build says so when it does (a flag
    of the telling thread), a release build would stand still.
  - **`conditions::running::Running` still has two setters**, one for the settings and one for
    the conditions: `remote/`'s tests call them, and that area was another task's. The service
    and the registry have one function each.
  - **A helper's reconnect is as dear as before** (`F242`): the registry asks every account to
    resume, and a resume is a change of the folder, which stops its sync.

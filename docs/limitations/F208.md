- **F208. What the helper's bounds per uid on waiting opens and on roots leave open**
  (`konedrive-helper/src/jobs.rs` `MAX_SUSPENDED_OPENS_PER_UID`, `roots.rs` `MAX_ROOTS_PER_UID`
  and `Roots::with`, `registration.rs` `register_root`; quality findings `HE1`, `HE2`) — one uid
  can no longer hold every descriptor the helper has, nor grow `roots.json` without end. What the
  bounds do not cover:
  - **An open is charged to the file's owner, not to the opener.** A permission event carries no
    uid for the opener, and the descriptors are held for as long as the owner's daemon is
    silent. So a user who can read another user's placeholders can spend that user's 8192: while
    one large file of theirs is being filled, each further open of it waits and is counted, and
    past the bound the owner's own opens are refused `EAGAIN` until the fill ends. It needs
    files the owner made readable to the other user, and it ends by itself.
  - **The bound is per uid, with no bound for the machine.** Eight uids whose daemons answer
    nothing reach the unit's 65,536 descriptors together. One hostile user is one uid.
  - **A legitimate burst above 8192 opens waiting at once for one user's daemon is refused
    `EAGAIN`** beyond the bound. The largest measured is the VM suite's 3000.
  - **A user with more than 32 intercepted folders** is refused the 33rd (`EDQUOT`); the daemon
    shows it as the helper refusing the registration. One folder per account, so 32 accounts.
  - **Roots already in `roots.json` are not checked again.** An entry stored before the id's
    form was checked, or a uid's entries beyond 32, stay, are walked at every start, and can be
    unregistered; a log line that names such a stored id prints it escaped and cut.
  - **A displaced root is unmarked only where its stored path still leads to it.** When an id is
    registered onto another directory, the old directory is found again by its path and checked
    by `(dev, ino)`, as an unregistration does (Z7). A folder replaced *at its path* by a copy,
    with the old one renamed aside, is not found: its tree keeps its marks until the helper
    restarts (opens of its placeholders answer `EIO`), and reads zeros after, like any copy of
    placeholders outside a registered folder. An old directory that was deleted lost its marks
    with its inodes. The log names the condition.
  - **An id does not move onto a directory inside its old one, or containing it,** while the old
    one is still at its path: refused `EINVAL`, because unmarking the old tree would leave the
    part the two share unmarked until the new walk (zeros). The daemon shows it as the helper
    refusing the registration; it does not ask this by itself. Unregistering the id first is the
    way through. Whether the two overlap is judged by their paths.
  - **A displaced registration is two full walks in one request** (the old tree unmarked, the
    new one marked), under the daemon's single 120 s bound for `register_root`
    (`konedrived/src/helper/mod.rs`). On a very large tree the daemon can give up while the
    helper finishes; the registration is in place by then, and the daemon's next attempt, with
    the same id, is an ordinary re-registration. F3 is the same weakness for one walk.
  - **A refused registration of an id the helper already holds can cost the old folder its
    registration, through the daemon.** When a *fresh* registration fails, the daemon lets go
    of it (`konedrived/src/sync/registration.rs`, `abandon`): it sends `UnregisterRoot` with
    the id it tried. If the helper holds that id for another directory — the refused overlap
    above, or any other refusal of an id that is already registered (the bound is not one: it
    is not asked of an id held) — that request unregisters and unmarks the *old* folder, whose
    placeholders then read zeros like any outside a registered folder. `abandon` treats the
    answer as its own registration undone and restores the folder it had before. This is as on
    `dev` for every such refusal; it needs a folder that carries the id of another folder still
    registered, which the daemon does not make by itself (a copy with its attributes does).
  - **The old directory of an id is opened by its stored path, on the request's own connection
    thread, with no lock held.** A mount that never answers, put by the peer over a component
    of that path, holds that one connection of the peer's and nothing else, as it does for an
    unregistration. If the id's entry changes between that open and the decision (the same uid,
    from another connection), the request is refused `EAGAIN` with nothing changed; the daemon
    shows it as the helper refusing the registration, and the next attempt is decided on what
    is there then.
  - **What is throttled, and what is not.** Each key writes one line in five seconds and a count
    for the rest. `RootRefused`, one key for all uids: a registration or unregistration that
    is refused — the id's form, the bound, an overlap, a directory that is not the peer's, a
    path that does not lead back, a filesystem that cannot be used or does not have what
    placeholders need, an entry that changed meanwhile, an id that is not the peer's to
    unregister. `RootIdTaken`: an id that belongs to another user, apart, so that a flood of
    the others does not hide it. `RootsNotSaved`: a `roots.json` that cannot be saved. These
    lines are warnings now, where some were errors. Within a key, a flood by one user reduces another user's line
    to a count, the uid with it: there is no key for each uid, since that is a map a peer could
    grow. Not throttled:
    - what a registration that *succeeds* writes (the walk's count, a degraded walk with its
      failures, a displaced root's unmarking), one set for each request, each costing its
      sender a walk of the tree;
    - the lines of the helper's start, one for each root that is not covered. A root on a
      filesystem that cannot be used is said there in the start's own line, with the reason;
      the throttle is not involved;
    - outside registration, as on `dev`: "cannot stat an object sent by uid N" and "a mark
      request failed" (`konedrive-helper/src/connection.rs`, `apply` and `act`), which a peer
      can cause with every request. They carry a uid and an errno, no string of the peer's.

    A walk's failures are written 16 at most, then counted; each keeps its reason whole, with
    its path escaped and cut. Every path and every id in these lines is escaped and cut (200
    and 40 characters) unless it is a root id.

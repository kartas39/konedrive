- **F268. A roll-back that fails leaves the file `hydrating`, not `online-only`** (`hydration/demote.rs` `demote`;
  `hydration/source/fill.rs` `roll_back`; quality finding `HY2`) — a failed fill, a stopped
  download, a free-up and startup recovery empty a file with one function and in one order:
  the punch, the size, the times, `fsync`, and only then `online-only`. The first step that
  fails ends it, and the file stays in the state it was found in. Before, a failed fill's
  roll-back wrote `online-only` first and went on past every error, so a punch that failed
  left an `online-only` file with part of a download in it. What the new order leaves:
  - **After a roll-back that itself failed** (an `fsync` or a punch refused by a failing
    disk) the file reads `hydrating` with whatever was written. The next intercepted open
    fills it again, and startup recovery resets it. Until then `Hydrate` of that file in an
    intercepted folder whose helper is away is refused (`NotCleared::NoWay`: a file that is
    not `online-only` is filled only with a way to clear its mark), where an `online-only`
    file would have been filled; and `Dehydrate` answers `NotHydrated` as before.
  - **The sync passes over the file while it reads `hydrating`.** The materializer defers a
    file in an interrupted state every cycle (`remote/materialize/file.rs`, `check_file`,
    counted in `deferred`; in a read-write folder its row waits in `content_waits`), so a
    change of that item in OneDrive is not applied to it, and the examination looks at it
    again in every pass, until an intercepted open or a restart repairs it. This is what a
    fill dropped part-way (F230) and a free-up cut off already left; the roll-back that
    fails is one more way into it. Not repaired in the cycle: emptying the file there needs
    the helper asked to clear its mark and a write lease, which the materializer, on its own
    thread under the tree lock, does not have.
  - **Every roll-back now costs an `fsync`**, on the path of a fill that has just failed,
    possibly on a full or failing disk.
  - **A stopped download** (`back_to_placeholder`) keeps the time of its last write, as a
    file reset by startup recovery does; the next Full reconcile puts the cloud's time back.
  FRAGILE · reasoned · open. Not zeros in any of these: a file that reads `hydrating` is never
  let through by the helper and never ignore-marked.

- **A22. The kinds and copies are read by their codes; the reasons' words are the catalogue's.**
  FRAGILE · reasoned (`modelstest::uploadKindsAndCopies`). `uploadReasonText`
  (`app/uploadreasons.cpp`) turns an outbox row's reason, an `upload-failed` detail and a
  `NotUploaded()` reason into the window's words. Since issue #199 the sentences are written
  once, in `crates/konedrive-text`, for the window and `konedrivectl` both (the window's are
  generated into `app/generated/reasontexts.cpp`), and a test holds them against the codes; a
  code with no sentence is shown as the daemon wrote it. What is still written for each client
  is D60. The worker's own retry reasons (`changed-while-sending`, `parent-not-in-onedrive`, …) are shown as
  codes, as the command line shows them. `Conflicts()` carries each entry's kind (`rescued` or
  `copy`), and the window and `sync conflicts` word them by it; the `conflict` event carries none,
  so there a copy of a file changed on both sides is told from a rescue by where its other file is:
  beside the original (a copy) or anywhere else (a rescue). A rescue into the same folder, which the
  daemon never makes, would read as a copy in the Activity list. Open.

- **F260. A helper that does not answer holds the folder's tree lock for one timeout in every
  examination that asks it.** LIMIT (chosen), *measured* with a stand-in that times out
  (`local::tests::liveness::a_helper_that_times_out_is_asked_once_in_a_run`); no test has the
  real helper hang (D46). Open. The examination asks the helper where a missing object is
  (`OpenByHandle`, F54) with the tree lock held (`local/watcher/service.rs`), because a cycle
  that changed the folder between two asks would change it under a half-made decision. Each
  ask waits for the helper link's call timeout (30 s; 45 s at the most, `ASK_WITHIN` in
  `local/liveness.rs`). After the first ask that times out, the run asks nothing more
  (`Run::place_of` in `local/examine/place.rs`; quality finding `LO10`): everything it would have
  asked after is undecided, nothing is deleted, and the places are examined again after
  `RECHECK` (30 s). So a helper that stays silent still costs one timeout in each such
  examination, during which nothing from OneDrive is applied to the folder: about half the
  time, for as long as items are missing and the helper hangs. In practice the first timeout
  also ends the connection (`helper/link.rs`), and until the link is back every ask fails at
  once (`NotRunning`), which holds nothing. Only a timeout sets the flag; a refusal or a
  missing helper answers at once and is asked again for the next item.

- **R8. The version is one line in `Cargo.toml`, bumped by hand after each release.** FRAGILE ·
  reasoned · mitigated. `[workspace.package] version` is the next release's; a build that is not a
  release carries `X.Y.Z-dev.N` (`~dev.N` in RPM), `N` the commit count of `HEAD`'s history
  (`docs/releasing.md`). (1) `N` counts `HEAD`'s own history: a package built from a branch can
  carry an `N` above a later `dev` build's, and `dnf` then takes that later build for a downgrade.
  Packages are built only from `dev` (`docs/releasing.md`), so this holds by rule, not by code. (2)
  Forgetting the bump pull request after a release leaves the file at the released version: the next
  merge into `main` builds it again, and the workflow stops at the tag step (`vX.Y.Z` exists on
  another commit) until the file is bumped. Safe, but manual. (3) A plain `cargo build` (and
  `scripts/dev-install.sh`) shows `X.Y.Z-dev` with no `N`, and a plain CMake build the same; their
  commit is `git rev-parse HEAD` when the build ran (Cargo reruns the build script when `HEAD`, the
  worktree's reflog `logs/HEAD`, the branch's loose ref or `packed-refs` changes; CMake configures
  again on the same files). The reflog is what catches a commit once git has packed the branch's
  ref: every commit, checkout and reset appends to it, while the commit writes a new loose ref that
  did not exist (so was not watched) and leaves `packed-refs` as it was. An uncommitted change is
  not marked, and with the reflog turned off (`core.logAllRefUpdates=false`) a commit on a packed
  branch can go unnoticed until the next build that reruns for another reason. Since the commit is
  compiled in, each new commit rebuilds `konedrive-dbus`, `konedrived`, `konedrivectl` and, in the
  window, everything that links `konedrive_core`. (4) `scripts/build-rpm.sh` rewrites lines by
  pattern (the `version` line of `[workspace.package]`, the `version` of every lock entry without a
  `source`, the spec's `Version:` and its `%global commit` and `%global build_version`) and stops if
  one it expects is missing; `cargo vendor --locked` stops it if the lock file no longer fits. The
  window's CMake reads the version from `Cargo.toml` with a regular expression, and stops
  configuring if it finds none. (5) The user agent sent to Microsoft Graph carries Cargo's own
  version (`X.Y.Z` in a plain build, without `-dev`). (6) The window compares the daemon's `Version`
  and `Commit` with its own exactly, as it reads them each time the daemon appears on the bus (both
  are constant): two builds from the same commit and version look the same, and a daemon from before
  the properties counts as another build ("Service: an older version").

- **R12. The window's QML is compiled into the binary, because Qt's disk cache kept a same-day
  build's.** WORKAROUND · measured · mitigated (fixed by #88). The window's QML used to be a plain resource
  (`qt_add_resources`), compiled at its first load into Qt's disk cache,
  `~/.cache/konedrive/qmlcache`. Qt keeps using a resource file's cached unit for as long as the
  executable's modification time is unchanged, and rpmbuild sets every file's time to the
  changelog's date, which has no time of day: every package built on the same day installs
  `/usr/bin/konedrive` with the same time, and after the second build of a day was installed the
  window ran the first build's QML (an Activity page with the old pool line, against a new daemon).
  Now the QML is a module of its own, `org.konedrive.app.window` (`qt_add_qml_module` in
  `app/CMakeLists.txt`), which qmlcachegen compiles into the binary; the window loads it with
  `loadFromModule`, and Qt never looks its files up in the disk cache. The C++ types stay
  registered imperatively in `org.konedrive.app` (`app/qmlregistration.h`), which qmlcachegen
  cannot see, so what uses them is compiled to bytecode, not to C++. Units that earlier builds left
  in `~/.cache/konedrive/qmlcache` under the old `qrc:/` paths stay on disk, unused; nothing removes
  them. Test: `qmlcachetest` loads the window with the disk cache on, in an empty cache, and finds
  no unit written for the window's files (and one for a plain resource file, which shows the cache
  is on).

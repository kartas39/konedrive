- **D35. Refusals and the notes of `LastError` are types over the strings they were.** DEBT,
  *measured* (`konedrive-dbus`'s `refusal::tests`, `konedrived`'s `dbus::fault::tests`,
  `status::snapshot::tests` and `account::state::tests`, `konedrivectl`'s
  `text::refusals::tests`), open. The name a call is refused under is a `Refusal`
  (`konedrive-dbus/src/refusal.rs`): the daemon answers through it (`dbus/fault.rs`, one `Fault`
  for every interface) and `konedrivectl` reads a reply into it once. The sentences of
  `konedrivectl` are grouped by action (`text/refusals/folder.rs`), each group a match over every
  `Refusal`. The mode's note, the note of a failed switch to interception and the outbox's note
  are slots of the snapshots (`account/state.rs`, `status/snapshot.rs`), joined where `LastError`
  is read (quality findings `X1`, `CL2`, `CL3`, `AC4`, `SY6`). No name, sentence or text changed,
  so what the strings were is still there:
  - **The names.** The window's and Dolphin's tables (`dolphin/src/refusaltext.cpp`,
    `app/synccontroller.cpp`) are keyed by the names as text; nothing checks them against the
    enum. `Refusal::ALL` is written by hand: a variant left out of it is not read back from its
    name (it becomes `Other`). The test does not compile until a new variant is spelled there
    and counts the list (28); it cannot see a variant missing from the list by itself.
  - **Which names the enum has.** The daemon's twenty-two, the bus's `InvalidArgs` and `Failed`
    (`Refusal::BusFailed`, beside the daemon's own `Failed`), the three the object server
    answers for what is not there, and `org.freedesktop.zbus.Error` (`Refusal::Internal`). Every
    other name (`NoReply`, `ServiceUnknown`, `AccessDenied`, a later version's) is
    `Refusal::Other`, kept as it came and worded as a call that failed. `Refusal::from_error`
    reads a `zbus::Error::MethodError` and the `Error::FDO` a failed read of a property comes
    back as.
  - **A refused ignore pattern goes out under `org.freedesktop.zbus.Error`**, with
    `org.freedesktop.DBus.Error.InvalidArgs: ` at the start of its message, not under
    `InvalidArgs` as `dbus/org.konedrive.Folder.xml` and the proxy's comment say
    (`dbus/fault.rs`, `to_fault`, `SyncError::InvalidArgs`). It did before; it is kept, and a
    test pins it. `konedrivectl sync ignore` prints it as "changing the ignore list failed: …".
  - **Data still travels inside the daemon's sentences**, and `konedrivectl` cuts it out again:
    the path refused and what pins it (`NotAllowed`: `<path> is pinned by <folder>: unpin it
    first`, `hydration/pin.rs`; `text/files.rs` `pinned_parts`), the path of a `NotUploaded`
    (`<path> is not uploaded yet…`, `sync/mod.rs`; `text/files.rs`, `text/refusals/folder.rs`),
    the path at the start of an `Unsupported`, and an `Unreachable` whose message begins with
    the error prefix (read as "no message"). `text::files::tests::the_daemons_sentences_are_read_back`
    reads the first two back from what the daemon writes, so a rewording fails a test; the others
    have none. Carrying the path and the folder as structured data would change the bus.
  - **A pair nobody wrote a sentence for gets another action's.** A group's match sends every
    refusal it has no sentence for to `shared`, which has the sentence written for whichever
    action was refused that way first: `NotEmpty` to `sync outbox` still reads " is not
    empty. A new sync folder has to start empty…", with no path. No such pair is raised today (`CL2`'s "Verified"). The
    registrations and the four lists have no sentence of their own and no match of their own:
    they go to `shared`.
  - **No test holds every sentence.** That the grouping prints what the one match printed, for
    every pair of an action and a name, was shown once, before the merge: a table of all pairs
    made from the function at `a165027` was compared with the grouped one, and the review made
    the table again by itself. The table is not kept. What stays is the hand-written tests of
    `text/refusals/tests.rs`, which hold the sentences somebody wrote a test for.
  - **An account's error and its mode note are two public fields kept apart by their
    setters.** `LastError` is the error, or with no error the note; each takes the other's
    place, as the one string did (`set_error`, `clear_error`, `set_mode_note`). So an error
    said while the account runs read-only against `config.toml` still hides why until the mode
    is worked out again, and code that assigns `last_error` directly leaves a note standing
    that the error then hides. The folder's `last_error` is the same with its `switch_note`:
    the note stands behind the registration's text and goes with any `set_error` or
    `clear_error`, and a direct assignment (two tests make one) leaves it standing.
  - **The outbox's note still has two writers**, the write gate and the read-only folder's
    poller, each writing over the other's; the gate takes back only a `GateClosed`.
  - **Still strings:** the folder's `watch_note`, `handles_note`,
    `held_back` and the sync's trouble (the replacement note is a type since `RE10`, with the
    failure's own words inside it); the upload worker's own `last_error`, whose gate
    message is still found again by its first words (`upload/engine.rs`, `GATE_CLOSED`); why
    the gate is closed (`gate_refusal`, a `String`); `SyncError::Io(String)` (the quality
    plan's `B5`); and, in `konedrivectl`, `RootSource` and the `Skipped()` reasons (the helper's
    states are `konedrive_dbus::HelperState` since `DB1`; `konedrivectl` still carries the
    property's text and reads it into the type where it words it).

- **F203. A free-up whose last step cannot be joined leaves the file `dehydrating`**
  (`hydration/dehydrate.rs` `dehydrate_opened`; quality finding `HY8`) — every failure the lease
  step reports rolls the state back to `hydrated`: a lease refused, and a lease that cannot be
  asked for. A panic of the blocking task that takes the lease and punches, or a runtime that is
  shutting down and never runs it, is answered with an I/O error and no roll-back: the file went
  into that task, and from outside nothing can tell whether the punch had begun, and a file
  punched and then labelled `hydrated` would read zeros. The file stays `dehydrating`, as after a
  cancelled free-up: the next open downloads it again, and the next startup recovery empties it.
  Never zeros. FRAGILE · reasoned · open.

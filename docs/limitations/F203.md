- **F203. A free-up whose blocking task cannot be joined leaves the file `dehydrating`**
  (`hydration/dehydrate.rs` `dehydrate_opened`; quality finding `HY8`) — every failure a step of
  the free-up reports rolls the state back to `hydrated`: a mark that cannot be made durable, a
  way that is not cleared, a lease refused, a lease that cannot be asked for. A blocking task
  that cannot be joined (it panicked, or the runtime is shutting down and never ran it) is
  answered with an I/O error and no roll-back, in three places:
  - the first task, if it dies after it wrote `dehydrating`: nothing is punched;
  - the task that rolls back after the way was not cleared ("the rollback task failed"): nothing
    is punched;
  - the task that takes the lease and punches: the file went into that task, and from outside
    nothing can tell whether the punch had begun, and a file punched and then labelled `hydrated`
    would read zeros.

  In all three the file stays `dehydrating`, as after a cancelled free-up: the next open
  downloads it again, and the next startup recovery empties it. Never zeros. FRAGILE · reasoned ·
  open.

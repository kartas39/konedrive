- **F60. `write_test_drive_ids` limits the read-write token export, and nothing else**
  (`konedrived/src/config/model.rs`, `Config::read_write_export_allowed`;
  `konedrived/src/account/mode.rs`, `read_write_token`; write design §2.3, §12.1) — the list
  was the development gate of the upload work: only an account whose drive was on it could be
  read-write. It no longer decides any account's mode, which is the user's choice (F294). What is
  left: a development build's `TokenExport.ReadWrite` hands a token that can change files out
  only for an account whose recorded drive is in `write_test_drive_ids` in `config.toml`, read
  again at each call, and is refused `WritesNotAllowed` otherwise; the list is empty by default,
  and nothing in the daemon writes it (the developer install sets it to the test account's drive
  by hand). The token is then asked which drive it reaches, and another than the listed one is
  refused the same way and turns the account read-only (F61). `konedrive-write-test` reads the
  same list for its own check of `--graph-test-drive` (F130), and the upload stress tool for
  its check that `--account` is a test account (W19). The released package has neither
  the interface nor the command (W11).
  What the outbox's write gate still asks, before each row the worker takes and between an
  upload's fragments (`sync/mode.rs`, `Gate::refusal`): the folder and the account
  read-write, `config.toml` read again saying read-write and recording a drive for the account
  (a file that cannot be read closes the gate, and an account with no recorded drive is
  read-only), the drive the account's token was last seen to reach being that one, the token
  able to write, and the folder's sync not stopped by another account's drive or a sign-out.
  Closed, nothing more is sent, the rows wait, the folder's `LastError` says why, and the
  account's mode is worked out again, which turns it read-only (F140) — so an edit of
  `config.toml` counts at the next row, not at the next token refresh. Writes are still addressed
  to `/me/drive/items/…`, not to the recorded drive: what holds them to that drive is the gate's
  comparison with the drive last seen, and the sync's own same-drive check at every cycle.

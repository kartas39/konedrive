- **F290. After a panic under a lock, the next user of the lock goes on with the data as the panic left it**
  (`konedrived/src/panic.rs` `lock`, `read`, `write`; `konedrive-graph/src/lib.rs` `lock`;
  `konedrive-tree/src/outbox/changes.rs` `dirty`; quality finding `X4`) — every lock of
  `std::sync` in the daemon, `konedrive-graph` and `konedrive-tree` is taken whether or not a
  holder of it panicked. Before, about 95 of the 150 sites panicked in turn, so one panic under
  such a lock took every later user of it down too: a D-Bus call, a sync's cycle, the daemon's
  stop. Nothing checks that the data is whole; it is kept whole by what is done under each lock:
  - **Most locks guard one value or one collection**, and each change of it is one assignment,
    one insert, one remove or one take. A panic cannot be between two steps.
  - **Four run code they are handed while the lock is held**, and a panic in that code leaves
    what is listed here:
    - `sync/pause.rs` `show`: `publish` panics, so the pause shown is not remembered and a timed
      pause gets no timer. The next `show` starts it; until then a timed pause does not end by
      itself. `forget` stops the timer and forgets the pause before it calls `publish`.
    - `conditions/running.rs` `change`: the settings are plain values with no rule between
      them; what the closure had set stays set.
    - `daemon/manager.rs` `list`: the registry is told first and the account listed after, and
      the registry adds the account as its last step, so the account is in both lists or in
      neither.
    - `hydration/pin.rs`, every section that publishes the count or the waiting size
      (`state.update`): the queue and the set were changed before the publish, so they are
      whole and the published figure is the one before. The next change publishes again, and a
      sweep counts everything again from the folder.
  - **Two locks guard something outside themselves** and hold no data: `account/mod.rs`
    `cache_lock` (one read-modify-write of `account.json`, written by a rename, so the file is
    the old one or the new one) and `helper/hub.rs` `publishing` (the link is set and
    `HelperState` published; a panic between them leaves the state of before until the next
    `check`, which works it out from the link again).
  - `config/store.rs` keeps its own word "poisoned" for a `config.toml` that could not be read.
    It is not about a panic, and nothing of it changed.

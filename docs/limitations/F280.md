- **F280. The removal of an empty copy opens its entry by itself, not through the examination's
  one open** (`konedrived/src/local/examine/classify.rs` `remove_empty`) — every other open of a
  listed entry goes through `Run::open_same` (F275). `remove_empty` opens the name itself and
  checks the descriptor against the listing in its own way (device and inode, a regular file
  with one name, the state read through the descriptor, no data region, the name checked
  against the descriptor again right before the unlink). It was left so because its answers
  differ on purpose: a copy it cannot open, or cannot prove empty, is *kept and listed*
  ("not downloaded"), where `open_same` would pass it over or fail the batch. The unlink
  itself is by name: between the last check and `unlinkat` a rename over that name removes
  another file — the window every removal by the daemon has (F53); Linux has no
  unlink-if-same-object. Both go when the examination's disk writes get one door (quality
  findings `LO1`, `LO2`). DEBT · reasoned. Open.

- **D51. The helper's stand-ins are one module for the daemon's own tests, not for the tests outside the crate.** DEBT,
  *reasoned*, open. `helper/testing.rs` holds the socket, the greeting and the answer loop of a
  fake helper, in two shapes: `fake_helper(path, answer)`, whose answers are a closure of the
  test's (`helper/link/tests.rs`, `hydration/dehydrate/tests.rs`, `hydration/server/tests.rs`),
  and `FakeHelper`, which records, refuses, holds an answer back and finds an object by its
  handle (`sync/`, `remote/`, `upload/`, `local/`, `hydration/server/tests.rs`). The upload
  tests reach it through a real link, where they had a stand-in for the link itself: a helper
  that is down is a link cell with no link, so a fill then has no clearance at all, where the
  old stand-in always answered "no helper is bound". Left:
  - one helper of `hydration/server/tests.rs` is still built by hand: it sends hydration
    requests of its own and holds answers back in an order neither shape has a way to say;
  - the tests outside the crate keep their own (D2);
  - `sync::testing`, built for the VM suite too (`fault-injection`), no longer exports a fake
    helper there: the suite runs the real one;
  - `RegisterError::Io` and `RegisterError::Unsupported` are one name on the bus
    (`SyncError::Unsupported`, `sync/mod.rs`): told apart in the daemon, not for a client;
  - no test checks the lines the link's reader now logs for a message it passes over.
  - no test makes a directory probe and then fail to open or list, the case `Disk::scan`'s
    one rule adds (F272): without root or a fault hook only mode `000` can be made, and that
    fails at the probe, as it always did;
  - a placeholder removed by `Disk::rescue` in place of a rescue (F277) is logged at `info`
    and counted nowhere: no Activity row says so, so `counts.deleted` does not either.

- **D37. The test support of `sync/` is built into the daemon's crate, and finds a service's parts by a list.**
  DEBT · reasoned, open. `konedrived::sync::testing` (a `Wiring` of fakes: the fake helper, the
  account, a temporary `config.toml`, the content sources, the watcher, a clock moved by hand) is
  compiled under the crate's own tests and under the `fault-injection` feature, which the VM
  suite's build turns on (and which brings `tempfile` in as a dependency then); the package build
  and `scripts/dev-install.sh` do not. A test gets what its service was made with from
  `testing::parts(&service)`, which looks the service up by address in a list kept for the whole
  test process; an entry leaves the list when a later service is made after its own is dropped.
  The fake account answers the folder from a state the test changes and only counts "work the
  mode out again" and "this drive was seen": what the real account does then (it turns
  read-only) is the test's to do by hand. `ManualClock` moves only the account's pause clock
  (`F100`). The fake helper answers on its one thread: while it holds an answer, every request
  behind it on that connection waits too. `testing::persist` is not async: it polls
  `ConfigStore::open` once by hand and panics if that waits, which holds only while `open` awaits
  nothing but the wallet check it is given, ready here.

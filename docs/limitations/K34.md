### K34. "Move to Trash" needs KDE Frameworks 6.21 or later to delete without a download

- **Why:** The sync folder has no trash of its own: the mount refuses a `.Trash` directory, which
  would be uploaded. From 6.21 on KIO then answers "no trash available" and the file manager asks
  to delete instead. Before 6.21 KIO fell back to the home trash, which is on another device: a
  move there is a copy and a removal.
- **Effect:** With KDE Frameworks before 6.21, moving a file to the trash downloads it whole into
  the home trash and removes it in OneDrive. From 6.21 on nothing is downloaded and nothing lands
  in a local trash; a program that calls `KIO::trash` and asks nothing gets the error and the file
  stays.
- **Stays because:** In KIO before 6.21 only a trash directory that exists inside the mount avoids
  the copy, and the folder is to hold none. KDE Frameworks 6.21 is the least supported version.
- **Where:** `docs/kio-behavior.md` §D; `crates/konedrived/src/mount/upload_rules.rs` (`is_trash`)

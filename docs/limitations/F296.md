### F296. The sync folder is not served while the daemon is not running

- **Why:** The folder is a FUSE mount: every name comes from the daemon's store and the content of
  a file that is not on disk from OneDrive. A mount lives only as long as the process that serves
  it.
- **Effect:** While the daemon is stopped, restarted or upgraded the folder is the backing
  directory: it shows the downloaded files and the user's own unsent files, without their write
  bits, and no file that is not on disk. A program that held a file open gets an error. After a
  daemon that was killed, every path in the folder fails with "not connected" until the unit's
  tidy step or the next start takes the dead mount off.
- **Stays because:** Showing every name without a process would need a file on disk for each, and
  something with root's rights to notice when one is opened.
- **Where:** `crates/konedrived/src/mount/tidy_step.rs`,
  `crates/konedrived/src/mount/stale_mount.rs`

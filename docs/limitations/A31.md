- **A31. While a wallet prompt is open at the end of a sign-in, the other changes of the accounts wait.**
  LIMIT · reasoned. The account of `Accounts.SignIn` is made with the manager's lock held, and its
  token is stored under it: a wallet that asks the user (KWallet to be opened) holds the lock until
  it is answered. Meanwhile every other call that changes the accounts or the settings waits:
  `SignIn`, `Remove`, `SetClientId`, `SetPauseOnMetered`, `SetOnBattery`, and `DevTools.AddAccount`.
  `CancelSignIn` does not wait, and answers `false`. The question to Graph about the other
  accounts' drives is asked before the lock is taken. Storing the token outside the lock would let
  a `Remove` or a second sign-in run between the entry and the token. Open.

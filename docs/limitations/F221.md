- **F221. One refresh at a time, and a cached token handed out beside it**
  (`konedrive-graph/src/token.rs`; quality finding `GR5`). FRAGILE, *reasoned*, open.
  The token manager has a refresh lock, held across every request to the token endpoint and
  everything that changes the stored refresh token, and a cache of two tokens (the account's
  own, and a read-write account's read-only one) behind a lock that is never held across a
  wait.
  - **A call that needs a refresh still waits for a read-only refresh under way**, and the
    other way round: the two share the refresh token and its rotation. Only a call that
    finds a fresh cached token does not wait. `TokenExport.ReadOnly` is called by hand, in a
    development build (W11).
  - **`invalidate` does not wait for a refresh under way.** Before, it waited and dropped the
    token that refresh cached. After a `401` (`drive/mod.rs`, `drive/write.rs`,
    `account/sign_in.rs`) that token is newer than the rejected one, and is kept.
    `switch_to_read_only` (`account/mode.rs`) calls it to drop a token that can write, with
    nothing rejected: a read-write refresh under way then ends afterwards and leaves a
    token that can write in the cache. It is not handed out: it carries what it was asked
    for (`asked`), `recompute_mode` has installed the read-only client before `invalidate`
    is called, so the account's own token is refused as asked for under another scope and
    refreshed down, and the read-only token is chosen by what a token is valid for. The
    `asked` tag carries this case.
  - **A cached token can be handed out while `commit_as` or `forget` runs**, until they
    replace or clear the cache: the same token a call a moment earlier would have got.
  - **On an `invalid_grant` answered to a read-only refresh, the account's own fresh token
    is still handed out** while the stored refresh token is deleted, until the cache is
    cleared (`refresh_with`).
  - **`the_accounts_own_token_does_not_wait_for_a_read_only_refresh` rests on a delay**
    (`token/tests.rs`). It asks for the account's own token once, without waiting, while the
    read-only refresh is under way, and then checks that the refresh has not ended. The
    refresh answers after two seconds: a test thread that stalls longer than that between
    seeing the request and asking fails the test, and cannot pass it wrongly.

  recorded yet included** (`konedrived/src/sync/upload/content.rs`, `stop_between_fragments`,
  `removed`; issue #36) — before each fragment the file is looked for as a run's start looks for it
  (`locate`: the row's name and the names of the rows behind it of the same object). Not found, the
  upload ends: a `create` as F149 ends it, an `update` alone with no event of its own (its session
  cancelled; the version OneDrive has stays until the `delete` or `move-out` behind it, or one the
  examination records later, deletes it). An `update` whose file is gone when its run starts ends
  the same way, instead of retrying as `not-found` every 30 s with the `delete` behind it waiting.

  it starts over from zero — the bytes sent are lost; (2) the look is a few `stat`s and one store
  query per fragment (10 MiB), taken on trust as cheap; (3) a removal during the last fragment, or
  during a one-request upload (up to 10 MiB), is not seen in time: the file is sent whole, then the

- **F247. An activity event of a kind this version does not name is left out of the log**
  (`konedrive-tree/src/activity.rs` `ActivityKind`, `recent_activity`; quality finding `RE11`) —
  FRAGILE, *reasoned*, open.
  What an event records is one enum, `ActivityKind`, kept in the store and sent on the bus by its
  name. The store's column is still text, so a store written by another version can hold a name
  this version does not have. Such a row is not an error: `ActivityLog.Recent` leaves it out, and
  it goes when 200 newer events push it off the log. So after a downgrade, or after a kind is
  renamed, part of the log is not shown until it is pushed out; nothing says that rows were left
  out. `Recent(n)` reads the newest `n` rows first and leaves out afterwards, so it can return
  fewer than `n` while older rows exist. A kind added to the enum needs its name in the window's
  table too (`konedrivectl`'s test of `ActivityKind::ALL` guards that).

- **F255. A file under an ignored name keeps a folder that can no longer be placed on disk**
  (`konedrived/src/remote/materialize/removal/unplaced.rs` `differs`, `remove_unplaced`) — a file that holds
  anything, or a directory that holds anything, under a name on the ignore list (`*~`, `*.tmp`,
  `.~lock.*#`, …) is never uploaded and is only on this computer. Inside a folder that can no
  longer be placed it is not removed: the folder waits, and the skipped list says "is only here (its
  name is on the ignore list)" with the path, until the user moves it out or deletes it. Until
  schema 7 such a file did not keep the folder and was deleted with it. What still goes with the folder,
  removed by the daemon: an empty file or an empty directory with an ignored name, a symlink, a
  socket, a FIFO, a device node, and a file of the user's own named `.konedrive-…` (the daemon
  takes every such name for its own). The same holds
  for a file from another folder that is not downloaded (it cannot be uploaded, and removing it
  could remove what another account's move out still waits to fill). Chosen as the option that
  deletes nothing; a question for the owner (pull request of `B4-6`). DESIGN · measured
  (`remote::listing::rw::tests::stale::a_file_that_cannot_be_read_and_one_only_here_keep_the_folder_and_say_why`),
  the file that is not downloaded reasoned · open.

- **F256. The step to schema 8: what of a leave under way is carried over, and what is not**
  (`konedrive-tree/src/schema/migrations.rs` `leaving_waits`; write design §9) — a store of schema 7
  may hold rows of `leaving`: items the base no longer placed whose objects stayed on disk until
  what waited in them was uploaded. The step makes each one an item the base places again, where
  its object is, with OneDrive's row of it as its deferred change (F188), and drops the two tables.
  - **Carried:** the row's path names a folder `items` places and no other item is placed at that
    name. The item's own content row is turned into one against that place, so it sends no name.
    What the base has below it is placed with it, with no object on record; an examination records
    what it finds in place.
  - **Not carried, only dropped:** the item is placed again elsewhere, its folder is not in the
    base, the path is not UTF-8, or another item is placed at that name. Its object is then nobody's
    item: a downloaded file in it goes up as new (a second file in OneDrive), one that is not
    downloaded is listed as not downloaded until the user removes it. The `update` rows at or below
    such an object are removed (their content goes up as new instead, and the upload session they
    opened is cancelled as any given up); a `create` or `mkdir` there forgets its recorded folder
    and asks the directory again.
  - **A folder before what was leaving inside it**: the inner one is carried into the outer.
    What the base has below a carried item is placed with it and records no object.
  - **A change of the item that already waited** in `deferred` is kept (it is newer than the
    base's row), and only dated so that no commit on record supersedes it.
  - **An object inside a leaving folder whose item OneDrive removed since** was removed by the next
    cycle of schema 7. One left by a cycle that failed in between is a copy now: uploaded as new if
    it is downloaded.
  - **A file or folder inside a leaving folder that OneDrive renamed or moved while it was
    leaving.** The base has it under its new name, with no object on record, and the object stands
    under the old name. A downloaded one is a copy: it goes up as a second file. One that is not
    downloaded cannot be uploaded and is not removed: it keeps the carried folder waiting, and the
    skipped line says "… is not downloaded and is not where OneDrive has it. Move it out of the
    folder." The way out is the one the line names: once the file is moved out of the
    folder, or opened (which downloads it, and it then goes up as a second file), the folder leaves
    at the next cycle. Deleting it works too for such a leftover (nothing is sent for it), but the
    line does not advise it: the same line is shown for a placed file's placeholder the user just
    moved in, whose delete would be sent. `konedrivectl sync skipped` prints the same line.
  - **A content row whose file has another name than the base has for its item is removed**,
    because it would send the old name back. The step cannot tell a rename made in OneDrive from
    one the user made under version 7 (which that version did not send): the user's rename plus
    an edit inside a leaving folder ends as a second file in OneDrive under the new name, and the
    item keeps its old content.
  - **A new file's upload cut in the middle under a folder that is not carried** can finish into
    the folder it was started for (the session holds its parent), and the examination then takes
    the file, which carries no id of this base's folder, for a new one: uploaded twice.
  - **`leaving-not-found` rows** are ready again; the file goes up as new if OneDrive still answers
    `404`. `mounted-inside` skips become `other-device`, `unknown-state` skips are dropped.
  - **Every row the base does not place loses its recorded object** (F245).
  - **A build older than schema 8 that opens the store rebuilds it** from a full listing, and its
    outbox is lost with it (a downgrade), as before (F189).
  - **The two installed stores were upgraded on copies** (about 30 900 items each, no leaving row
    and no outbox row): schema 8 in about 170 ms, every row as before. The leaving shapes are
    proved by hand-made stores only: `schema/tests/v7.sql` is written by hand in the shape `dev`
    at `98b14f5` leaves, and the test through the daemon makes its version 7 by rewriting a
    version 8 store in place (D45).

- **D50. What `dbus/` and `daemon/` still share by hand.**
  DEBT · reasoned (part 6 of `B5`, quality findings `SY9`, `SY10`) · open.
  - **`Bus` has three methods, not two.** `export` and `unexport` of an account, and `serve`,
    which puts the manager's own objects on the bus and starts announcing `HelperState`: the
    startup is in `daemon/`, which is below `dbus/` in the layer order and cannot name it. The
    trait has one implementation in the daemon (`dbus::export::OnBus`) and two in the tests
    (`tests/accounts.rs`: an export that fails, a `serve` that waits).
  - **The task that announces `HelperState` is nobody's, and never ends.** `OnBus::serve` starts
    it and lets it go. Through `Accounts` on the bus it holds the account manager, and so the
    hub whose state it follows: it ends with the process, and a test's daemon keeps its manager
    and its connection alive through it, as the task in the startup did before (F273).
  - **The totals are counted by a task the service starts and aborts as it is dropped**
    (`sync/mod.rs`, `status/totals.rs`), so `SyncService::new` must run on a tokio runtime (the VM
    suite enters its runtime for the whole run for that, `tests/vm/scenarios/main.rs`). The
    task holds the published state, not the service, and the abort in `Drop` is what ends it.
  - **Three rows still leave `upload/` and `status/` as tuples**: the uploads under way in the
    published state (`OutboxStatus.uploads`), `kept_back::SummaryRow` and what
    `kept_back::files` returns. `dbus/` names their fields as it builds the wire rows
    (`dbus/properties.rs`, `dbus/upload_queue.rs`); `sync/` passes the summary through as it
    comes. `Folder.Skipped` is still a pair on the daemon's side.
  - **`SyncService::items` is kept for the VM suite** (`tests/vm/scenarios/graph.rs`) and two
    tests; the bus does not read it.

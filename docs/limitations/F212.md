- **F212. Some failures of the tree store inside a reconcile still do not stop the folder**
  (`remote/listing/reconcile.rs` `drop_removed`, `hand_over`, `record`; quality findings `RE6`,
  `RE1`) — a store failure that ends a cycle is `CycleError::Store` where a call of the cycle's own
  or the materializer meets it: `RootState` reads `error` and the write gate is closed until a
  cycle goes through. Since the leaving mechanism went, every store call of a removal is one of
  those (`take_off` and what it asks the store while it looks at a folder that can no longer be
  placed). These are still not:
  - the read-write reconcile only warns when it cannot let the outbox wait for folders made again,
    or drop removals of items already gone;
  - `record` only warns when it cannot count what was listed, and the event says 0.

  A store that fails there usually fails at the commit too, which stops the folder; one that
  fails only there is seen in the log alone. DEBT · reasoned · open.

- **K32. The context menu waits for the daemon, and has no KOneDrive entries when it does not
  answer.** WORKAROUND · measured (`dolphin/tests/actionplugintest.cpp`: `noAnswerGivesNoEntries`,
  `aSelectionOutsideEverySyncFolderMakesNoCall`). What the menu offers is the daemon's answer
  (`Files.Menu`, issue #199), so the plugin keeps no copy of the daemon's rules. The cost: on
  every right click on something in a sync folder, Dolphin's UI thread waits for that answer, up
  to 300 ms (`SyncClient::MenuTimeoutMs`, chosen, not measured against a real folder). With no
  answer in time, no daemon on the bus, or an error, "Always keep on this device", "Free up
  space" and "Open in OneDrive" are simply not in the menu, with nothing said about why; nothing
  is decided from the marks instead. The call never starts the daemon, so with the daemon stopped
  there is no entry left to start it by a click, as there was before: it is started from the
  window, the tray or `systemctl --user`. A daemon that is busy takes longer to answer — a large
  selection (each path is looked at), or a selected downloaded file while the tree store is in use,
  since the answer asks the outbox about it as `FreeUp` does — and a right click then shows no
  entries; the next one asks again. A right click outside every sync folder costs no call (the
  root mark is read first, as for the emblems). open.

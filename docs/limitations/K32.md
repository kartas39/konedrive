- **K32. KOneDrive's entries in the context menu wait for the daemon, and are hidden when it does
  not answer.** WORKAROUND · measured (`dolphin/tests/actionplugintest.cpp`:
  `theEntriesWaitForTheAnswer`, `noAnswerHidesTheEntries`,
  `anAnswerAfterTheMenuIsGoneTouchesNothing`, `aSelectionOutsideEverySyncFolderMakesNoCall`).
  What the menu offers is the daemon's answer (`Files.Menu`, issue #199), so the plugin keeps no
  copy of the daemon's rules. The menu itself is never held up: the plugin hands its section over
  at once and asks asynchronously. The cost is in what is shown meanwhile:
  - Until the answer comes, "Always keep on this device", "Free up space" and "Open in OneDrive"
    are all three shown, disabled and unchecked, whatever the selection; then each is set, or
    hidden. So the menu changes under the pointer, and can get shorter while it is open. How an
    open menu redraws and resizes is the widget toolkit's, and was not looked at in a running
    file manager (the tests drive the actions, not a window).
  - With an error, no daemon on the bus, or no answer within two seconds
    (`SyncClient::MenuAnswerTimeoutMs`, chosen, not measured), the entries and the section are
    hidden, with nothing said about why; nothing is decided from the marks instead.
  - This holds for any host of the plugin (anything that loads `kf6/kfileitemaction` plugins:
    Dolphin, the file dialog, the desktop's folder view), not for Dolphin alone, and none of them
    was run.
  - The call never starts the daemon, so with the daemon stopped the menu has no entry to start
    it by a click: it is started from the window, the tray or `systemctl --user`.
  - A right click outside every sync folder costs no call (the root mark is read first, as for
    the emblems); one inside costs one call, answered or not, each time a menu is built.

  The daemon's side of the answer waits for no sync: one pass over the selection, and one
  question to the tree store's read-only connection (`sync/menu.rs`). A selection of many
  thousands of paths still takes as long as looking at each takes. open.

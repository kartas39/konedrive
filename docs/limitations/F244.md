- **F244. The plan of a reconcile is four queries for each item, inside one store job**
  (`konedrive-tree/src/plan.rs` `TreeStore::plan`; `konedrived/src/remote/materialize.rs` `plan`,
  `PLAN_BATCH`) — `plan(ids)` is one call of the store, not one SQL statement: for each id it reads
  the base's row and the new tree's row, and walks each one's chain of folders up to the root. The
  drive's root id is read once for the call.
  - **The store's thread is busy for the whole batch.** The materializer asks for at most
    `PLAN_BATCH` (500, a guess) items in one job, so that the jobs of others (the examination, the
    outbox worker, the downloads) run between two batches.
  - **A Full scan asks less.** It reads only the new tree's rows of what it found (`new_rows`, one
    query for each entry), and the plan only of the entries that are not where their item belongs.
  - **What would remove it:** one statement for a batch, over a temporary table of the ids, with the
    chains walked as `chains_sql` walks them.

- **D60. The words for the codes are written once, except those still written for one client.**
  DEBT · measured where a test is named, else reasoned; open. The sentences for a reason
  (`Reason`, `LocalSkip`, `WaitsFor`) and for a refused operation on a file (`Refusal`, for keep,
  unpin, free up and open in OneDrive) are in one catalogue, `crates/konedrive-text`, which
  `konedrivectl` reads and the window's and the Dolphin plugin's C++ is generated from
  (`docs/design/desktop.md` §2.10; issue #199). What that leaves:
  - **Written for one client, outside the catalogue.**
    - The window's refusals of its own operations (`AccountController::modeRefusalText`, the
      folder's in `app/synccontroller.cpp`, the accounts' in `app/daemoncontroller.cpp`) and `konedrivectl`'s of the commands no other
      client has (`text/refusals/account.rs`, and in `text/refusals/folder.rs` everything but
      `pin`, `unpin`, `free` and `open`): nobody else says them.
    - The reasons of `Skipped()` (`skip_reason_text`, `whyText`): they are not `konedrive-reason`'s
      codes, and are still two copies compared by a test (W12).
    - `sync status`'s reasons of the state as a whole, and the headings of `sync not-uploaded`
      and of the window's Not Uploaded page.
    - How the plugin sums up several failures (`failureSummary`, `dolphin/src/refusaltext.cpp`:
      "One more file was not … for the same reason."): plural forms, which the catalogue's
      sentences do not have outside `waits`.
  - **In the catalogue, for one client each.** Where the plugin and the command line said
    different things, both sentences were kept as they were (`Sentence::Each`), and where the
    command line had no sentence of its own for an operation it still says its table's
    (`Sentence::Desktop`). Three of these are the command line saying of one operation what was
    written for another, and were not improved:
    - `sync pin` and `sync unpin` without the helper say the registration's sentence ("… so
      <path> was not registered …"), where the plugin says what keeping or unpinning needs the
      helper for;
    - `sync pin` and `sync unpin` of a file changed here say what is said of freeing it up
      ("freeing its space would lose your edits");
    - `sync pin` and `sync open` refused `NotAllowed` say what is said of a free-up kept back by
      a pin ("… so its space is not freed up"), where the plugin shows the daemon's message.
  - **The command line prints the plugin's sentence with the path in the file's place**: the
    quotes of “file” stand around a path. Of several paths none of which the refusal names
    (`sync pin`, `unpin`, `free`), it says a list form instead, written for it alone
    (`RefusalText::several`, `FAILED_SEVERAL`: "<paths>: one of these is …"), which does not say
    which of the paths was refused: the daemon's message is not read for it.
  - **`sync hydrate` and `sync dehydrate` are not in the catalogue** (Dolphin has no such
    entry). Where their refusal is one a file operation has too, they say the catalogue's
    sentence for freeing up or keeping; `sync hydrate` of a file changed here still has its
    own copy of the sentence the plugin has for keeping.
  - **The plugin's names for the catalogue's operations and reasons are written in the
    generator** (`cpp/plugin.rs`: `Operation::AlwaysKeep`, `MenuAnswer::FreeUpWhy::PinnedAbove`
    from `pinned-above`). A renamed enumerator fails the plugin's build, not a test of the crate.
  - **The generated files are checked, not built, with the catalogue.** They are in git, and
    the C++ build does not run cargo: `cargo test -p konedrive-text` fails when one differs
    (`tests/generated.rs`, run on every pull request and before a release is built), and
    nothing stops a build made by hand (`scripts/build-rpm.sh`, `scripts/dev-install.sh`)
    from a tree in which they are stale.
  - **A sentence's places are numbered in the order they are first named**, so a translation
    made for the hand-written tables' `%1`, `%2` would not fit where the order changed (the
    plugin's "… requests are already waiting …"). There are no translations yet.
  - **The plugin's texts before and after are held by a file** (`dolphin/tests/refusaltexts.expected`,
    `refusaltextstest`), written once from the hand-written table for two messages (none, and one
    that names a folder above). A sentence changed on purpose is changed there too, by hand.

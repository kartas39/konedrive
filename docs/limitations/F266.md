- **F266. A walk asked for from inside a walk waits for the reader's next wake** (`konedrived/src/local/watcher/reader.rs`, `reader/timers.rs`) —
  when a walk of the folder finds the directory map out of step with the disk (a directory
  that would be placed below itself: only a lost event makes it so), it asks for one more walk
  "as soon as the queue is drained" (`Timers::lost`). That is not a timer: the reader looks at
  it after its next wait, which ends at the next event from the folder, the next hand-over, a
  flush, or a timer already running. In a folder where nothing happens the second walk can be
  late by as long as the folder stays quiet; the directory in question is not marked for
  interception, nor watched, until then. A change in the folder ends the wait, and the Full local
  scan that an overflow brings does not depend on it. Walking again at once was not taken: a map
  that stays out of step would make the reader walk without end. FRAGILE · reasoned (read in the
  code, not reproduced). Open.

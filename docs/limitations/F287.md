- **F287. A file whose marks are damaged is listed in Not Uploaded and left as it is; nothing
  repairs it** (`konedrived/src/local/examine/found.rs` `content`; `local/examine/copies.rs`
  `copy`; `konedrive-reason` `LocalSkip::BadState`) — a file that carries an item id and no
  `user.konedrive.state` konedrive can read (the attribute is gone, or holds a value no version
  writes) is never read, changed or uploaded by the examination. It now gets a line with the
  reason `state-unreadable`, in the group that needs the user for each file.
  - **The key is the one a blocked row has** for the same trouble found by the worker
    (`Reason::BadState`): one sentence and one sum for both. A file can be counted twice, once
    by its line and once by a blocked row at the same place.
  - **The way out is the user's.** The sentence says the file stays until it is replaced:
    saved again by a program that writes a new file over it, or copied without its attributes.
    The daemon does not guess the state from the file's content: a file full of zeros and a
    placeholder look the same.
  - **A copy with such marks** (an id that is not its own, and no readable state) is listed
    the same way, never stripped and never uploaded as new, though it may hold real content.
    Before, it was listed as `not-downloaded`.
  - **A directory has no state mark**, so this never applies to one. A damaged item id is not
    seen at all: the entry reads as carrying another id, or none.
  - **The line goes** when an examination looks at the place and finds a readable state, another
    file, or nothing; a batch that does not name the place leaves it (as every line of the list).
  - The journal line for each such file at each scan is written with debug logging only.

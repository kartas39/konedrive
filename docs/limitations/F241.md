- **F241. An intercepted folder whose root id is recorded nowhere is forgotten on the daemon's side
  alone** (`sync/persisted.rs` `recorded`, `sync/take_down.rs` `let_go_at_the_helper`) — the id
  is the name the helper holds a folder by. A `config.toml` written before the id was recorded
  names a folder without it, and the folder itself carries it (`user.konedrive.root`). When the
  folder is gone, or no longer carries the attribute, the daemon holds the folder as recorded,
  down, `State` `error`, with "config.toml does not record its root id, and the folder carries
  none that can be read" in `LastError`. A registration is refused `AlreadyRegistered` meanwhile,
  and the bring-up is tried at every connect and at a `Refresh`; it succeeds once the folder is
  back with its attribute. A Forget, and so `Accounts.Remove`, cannot tell the helper which folder
  to let go of: it takes the daemon's record away without the helper, touches nothing in the
  folder (no unlock walk runs in a folder that does not carry its id), and says in the journal
  that the helper could not be told. What follows:
  - **The helper may go on holding the folder** under an id the daemon never learns, with its
    marks, until `konedrive-helper` is restarted. A registration without interception of that
    folder made before then is the opening Z6 describes: a free-up there punches a file the
    helper still ignores.
  - **Only the journal says it.** `Unregister` and `Remove` answer nothing on success, so the
    window and `konedrivectl sync forget` report a plain Forget.

  Before the state was a type such a folder was not held at all: a Forget answered that there was
  nothing to forget, and a new registration was accepted over it at once.

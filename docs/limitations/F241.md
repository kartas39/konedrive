- **F241. An intercepted folder whose root id is recorded nowhere can be neither forgotten nor
  replaced** (`sync/persisted.rs` `recorded`, `sync/take_down.rs` `let_go_at_the_helper`) — the id
  is the name the helper holds a folder by. A `config.toml` written before the id was recorded
  names a folder without it, and the folder itself carries it (`user.konedrive.root`). When the
  folder is gone, or no longer carries the attribute, the daemon holds the folder as recorded,
  down, `State` `error`, with "config.toml does not record its root id, and the folder carries
  none that can be read" in `LastError`. A Forget is refused (`Failed`): it could not tell the
  helper which folder to let go of, and a folder the helper may still hold is never forgotten
  on the daemon's side alone. A registration is refused `AlreadyRegistered`. The bring-up is tried
  at every connect, and succeeds once the folder is back with its attribute. Otherwise the way out
  is by hand: take `[accounts.root]` out of `config.toml` and start konedrived again. Before the
  state was a type such a folder was not held at all: `State` read `error`, a Forget answered that
  there was nothing to forget, and a new registration was accepted over a folder the helper might
  still hold — the opening Z6 describes. An account held back refused the Forget already.
  LIMIT · reasoned (no test makes such a `config.toml`) · open.

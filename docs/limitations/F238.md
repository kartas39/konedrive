- **F238. A file with other names that is taken off the disk: what a stop between its unlink and the removal of its id leaves**
  (`konedrived/src/remote/materialize/removal.rs` `take_off`, `remove_whole`, `release_other_names`;
  issue #112) — when the daemon takes a file of its own off the disk and the file has hard links the
  user made, it unlinks the name first and takes the item id off the inode afterwards, through a
  descriptor opened before the unlink. So a stop between the two steps never leaves an object at the
  item's place without an id, which the examination would upload as new (#112).
  - **What the order leaves.** A stop between the two steps, or an id that cannot be taken off (it is
    logged and the cycle goes on: the name is gone, and no later cycle could do it), leaves the other
    names carrying the item's id.
  - **The daemon does not remove them.** Before the unlink, in the transaction that forgets the
    objects, a leaving row that follows such a file by its handle loses the handle
    (`leaving_forget_handles`): the other names carry the same handle, and the walk for a leaving
    object would otherwise take the one that is left for it and remove it. The row is then followed
    by its path only, as a row of a store from before handles were kept (F188); a save by rename at
    its place is still found, a parent renamed here before the next cycle is not.
  - **What the examination makes of them is not closed here.** It takes an object carrying the id,
    with no object on record and nothing at the item's place, for the item moved, and records a
    `move` to the other name's place: a move in OneDrive the user did not make. Invariant I2 of the
    B4 design (an object is the item only by its record or its place) closes it in `local/examine/`;
    `remote::materialize::rw::tests::a_stop_after_the_unlink_leaves_the_other_name_to_the_user` is
    ignored until then.
  - **The stop is made by a switch in the test build** (`removal::testing::stop_after_unlink`, per
    thread): nothing else can stop the daemon between two system calls.

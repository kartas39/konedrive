- **F250. An account's id and its drive are types only where `config.toml` is read and written**
  (`konedrived/src/config/ids.rs` `AccountId`, `DriveId`; quality finding `CF1`) — DEBT,
  *reasoned*, open.
  - **Where they are types:** the configuration (`AccountConfig::id`, `drive_id`,
    `write_test_drive_ids`), every call of `ConfigStore` and `Paths::account`, the account
    (`AccountService`, the identity guard, the wallet's `Slot::Account`), the manager's
    `Account::id` and the folder's `Persist::account`. There one given for the other does not
    compile.
  - **Where they are still text:** the drive the account's token was last seen to reach
    (`AccountSnapshot::live_drive`, `account.json`'s `drive_id`), the drive of the tree store
    and of the folder's attribute, what Graph answers, the listing's `DriveRecord::recorded`,
    `ModeNote::DriveMismatch`, and everything on D-Bus. A drive from there is made a `DriveId`
    at the call (`DriveId::new`, `None` for an empty text), and compared as text otherwise.
  - **Both read as `&str` where text is asked for** (`Deref`), so that paths, object paths and
    messages need no conversion. The price: either can be handed to a function that takes
    `&str`, and such a function cannot tell which it got.
  - **`AccountId` is not checked when made.** A hand-edited `config.toml` must load whatever
    its ids are, so an id is any text; `AccountId::is_valid` says whether it is one, and an
    account whose id is not is held and has no files, as before.
  - **An empty entry of `write_test_drive_ids` is not kept.** It names no drive and let no
    account's token export through before either; now it is left out when the file is read, and so is gone
    from the file at the daemon's next write. An empty `drive_id` of an account reads as no
    drive, as before, and is likewise not written back.

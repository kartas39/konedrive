- **F240. What the outbox worker is told without waiting is done only on the daemon's runtime, and its fault points are in the tests' build alone**
  (`upload/mod.rs` `detach`, `OutboxWorker::cycle_done`, `retry_now`, `quota_read`;
  `upload/engine.rs` `Engine::fault`, `arm`; quality finding `UP11`). FRAGILE, *reasoned*,
  open.
  - **A cycle that went through, a `Refresh()` and a quota read are handed to the worker as
    tasks of the runtime the caller is on.** Called with no runtime (a plain thread), the
    work is not done and the journal says so (`warn`). Before, `cycle_done` and `retry_now`
    built a runtime of their own there and ran the work to its end, a path only tests could
    take. Every caller in the daemon is on its runtime (`sync/outbox.rs`: the cycle's hook,
    `Refresh()`, the quota seen). A caller added on a blocking thread would lose the call;
    nothing checks for it at build time.
  - **The fault points** (`Fault`) fire only in the crate's own tests: the daemon keeps their
    names and no state for them, and a build with `fault-injection` (the VM suite's) cannot
    arm one any more. The suite armed none.
  - **The fake OneDrive** is the crate's `fake_onedrive` module (`src/tests/fake_onedrive/`),
    still built for the tests and with `fault-injection` only. The tests' worker around it
    (`upload/tests/harness.rs`) is test code of `upload/`, which `local/` and the bench use.

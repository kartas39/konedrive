- **F187. What is lost when OneDrive removes an item** (`konedrived/src/remote/materialize/removal.rs`
  `take_off`; write design §9; issue #104) — local work is kept and uploaded as new (F116). What can
  still be lost: a program that has an unchanged download open for reading and writes to it later by
  its path gets an error (the file is gone); what a program writes into a file it held open, after the
  cycle looked at it and before the file is uploaded, goes up with the file or, if the file was not
  kept, into an unlinked inode. A download in progress inside the item is stopped, and its opener gets
  `EIO` ("Input/output error"): the kernel delivers no errno that says the file is gone (quality
  finding `HY5`). A symlink, or an empty file with an ignored name, in a folder that holds nothing else of the
  user's goes with the folder. A file changed here whose item OneDrive removed is kept
  wherever it is, also inside a folder that waits to leave (F188).

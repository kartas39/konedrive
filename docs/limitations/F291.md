- **F291. What a pin worker does when it ends by a panic rests on how tokio drops a task**
  (`konedrived/src/hydration/pin.rs` `Worker`, `Pins::work`) — a worker that panics forgets
  the queue, clears `Queue::working` and leaves a sweep owed, so the next `add` starts another
  worker and the next cycle that succeeds queues the files again. The guard acts only while
  the thread unwinds (`std::thread::panicking`), which holds because tokio drops a task's
  future inside the unwind of its poll; a tokio that dropped it later would leave the queue
  marked as worked on, and `a_worker_that_panics_is_followed_by_another` would fail. The
  waiting size shown stays the one before until the next `add`: nothing is published in a
  drop during a panic. A download that panics is another case, caught where it runs and
  counted as failed.

- **D31. Some tests fail now and then when the machine is busy.** FRAGILE · measured (the
  failures) and reasoned (their causes), open. Seen in `cargo test --workspace` with other
  builds and test runs going on beside it (load average above 20), 2026-10-03. For each test:
  what was seen, what is known of the cause, and what is only supposed.
  - `upload::tests::pause_and_blocked_rows` (`konedrived`, lib; `pause_offline_sign_in_and_blocked_rows`
    until the worker's `online` went, quality finding `UP1`).
    *Seen:* `refused.txt`'s row `Ready` with `waiting-for-space` where the test expects
    `Blocked` with `refused: bad name` (`upload/tests/mod.rs:674`), once; the next run of the
    same code passed.
    *Known, from the code:* an ordering race in the test, which load only makes likelier. The
    engine runs the rows of a drain at the same time (`JoinSet`, `upload/engine/drain.rs`).
    `full.txt`'s `507` turns "OneDrive is full" on (`turn_full`, `upload/space.rs`); a content
    row that reaches `space_holds` (`upload/content.rs:50`) after that is held as
    `waiting-for-space` before it asks anything, so `refused.txt` never gets its `400`.
    *Supposed:* that this is what happened in the failing run; it was not reproduced on
    purpose.
  - `hydration::recovery::tests::recovery_holds_one_file_open_at_a_time` (`konedrived`, lib).
    *Seen:* 73 and 137 "more descriptors" against a bound of 64, in two runs of the whole
    binary on a busy machine; it passed run alone, and in one run of the whole binary on
    another checkout.
    *Known, from the code:* it counts the descriptors of the whole test process, before the
    walk and during it, so what the tests running beside it open in between is counted too.
    *Supposed:* that this is the whole cause; no run of the whole binary on a quiet machine
    was made.
  - `activity::binary_activity_lists_what_happened_newest_first` (`konedrivectl`, `sync_cli`).
    *Seen:* the test's `dehydrate` of the file it has just downloaded answered
    `org.konedrive.Error.InUse` ("the file is in use") (`tests/sync_cli/activity.rs:40`), once;
    the next run of the same code passed. Once more in a `cargo test --workspace
    --no-fail-fast` on another checkout the same day (what else the machine ran then was not
    looked at); not run again. Twice more on a third branch the same day: in a run of
    `sync_cli` alone and in a later run of the whole workspace; it passed in the run of the
    whole workspace between them.
    *Known:* nothing more; the cause was not traced.
    *Supposed:* the download still had the file open when the test asked to free it.
  - `a_version_1_onedrive_folder_is_held_then_brought_up_at_the_first_connect` (`konedrived`,
    `accounts`).
    *Seen:* `Folder.LastError` empty where the test expects the failed listing to be said
    (`tests/accounts.rs:683`), in both runs of the whole workspace made on one branch. Its
    binary run alone on that branch passed, and the runs of the whole workspace on four other
    branches the same day did not fail it: it fails now and then, in a run of the whole
    workspace.
    *Known, from the code:* the test reads `LastError` once, right after the folder carries
    its drive, and does not wait for it with `eventually` as it waits for the two things
    before it.
    *Supposed:* that the sync had not yet asked OneDrive when the test read it. It was not
    checked.
  - `local::watcher::tests::past_the_mark_budget_the_folder_is_scanned_on_a_timer` (`konedrived`,
    lib).
    *Seen:* the first batch handed over was not a Full scan (`assertion failed:
    next(&rx).is_full()`, `local/watcher/tests.rs:361`), once, in a run of the whole workspace
    at a load average of 27; three runs of the whole workspace on the same branch earlier that
    day passed it.
    *Known, from the code:* the test starts a watcher of its own and uses nothing of the
    daemon's sync; it takes whatever batch comes first for the timer's scan.
    *Supposed:* that a batch of events came before the timer's scan. It was not checked.

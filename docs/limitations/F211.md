- **F211. A folder whose `source` in `config.toml` is neither word is held, not repaired**
  (`sync/mod.rs` `Persisted::unread_source`, `sync/registration.rs` `source_brought_back`,
  `sync/resume.rs` `hold`; quality finding `SY6`) — `source` in `[accounts.root]` is `"onedrive"`
  or `"local"`; only a hand edit produces another value (`"OneDrive"`). The daemon does not guess
  which was meant: a folder brought back with such a word is not brought up, `RootState` reads
  `error`, `LastError` names the value, and `config.toml` keeps it as typed. A folder that is
  already up keeps the source it came up with, whatever is typed while the daemon runs. What
  follows:
  - **The way out** is to correct the word. A folder recorded with interception comes up at the
    next start, or at the helper's next connect: the file is read again then. Nothing in the
    window or in `konedrivectl` corrects the word.
  - **A folder recorded with interception** is held, so its Forget reaches the helper. Held, it
    reads `onedrive` in `RootSource`: a guess, used by the Forget alone, which takes off what a
    OneDrive folder carries (the read-only lock, the tree store, the Baloo exclusion `config.toml`
    records), whichever word was meant. For a folder that is in truth local this is not nothing:
    taking off the lock (`folder/disk.rs` `unlock_tree`) sets every regular file in the folder
    to 0644 and every directory to 0755, the user's own among them, so a 0600 file becomes
    readable by all and executable bits go. Nothing is removed or emptied.
  - **A mistyped OneDrive folder with changes waiting to be uploaded** can be neither forgotten
    nor removed with its account: the changes are counted in the store on disk
    (`sync/write_mode.rs` `changes_in_store`), and both answer `PendingUploads`. What that
    refusal advises cannot work here: the folder never comes up, and a forced switch to
    read-only drops nothing, because the store is not open. Only correcting the word and
    starting konedrive again helps.
  - **A folder recorded without interception** is not held: `sync forget` says there is nothing
    to forget, as for any such folder whose bring-up failed. A new `sync register` of it is
    accepted and replaces the record; otherwise the word is corrected by hand.
  - **What the commands say meanwhile** is not about the word: the outbox commands answer "the
    folder's sync has not started yet; try again in a moment", and go on answering it. Only
    `LastError` (the status) names the value.

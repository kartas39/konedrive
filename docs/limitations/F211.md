- **F211. A folder whose `source` in `config.toml` is neither word is held, not repaired**
  (`sync/persisted.rs` `Persisted::read`, `sync/folder.rs` `Down::UnreadSource`,
  `sync/bring_up.rs` `source_brought_back`; quality finding `SY6`) — `source` in `[accounts.root]`
  is `"onedrive"` or `"local"`; only a hand edit produces another value (`"OneDrive"`). The daemon
  does not guess which was meant: a folder brought back with such a word is not brought up, `State`
  reads `error`, `LastError` names the value, and `config.toml` keeps it as typed. A folder that is
  already up keeps the source it came up with, whatever is typed while the daemon runs. What
  follows:
  - **The way out** is to correct the word. The bring-up is tried again at the next start and
    at the helper's every connect, and nowhere else; it reads the file as it is on disk then,
    for a folder recorded with or without interception, so a corrected word counts without a
    restart once the helper connects again. Nothing in the window or in `konedrivectl` corrects
    the word.
  - **A file that cannot be read at that moment** (caught half-saved, or not valid TOML), or
    one that no longer records the folder, leaves the folder held too; `LastError` goes on naming
    the word it was held for, and the log says what the file was like. It is tried again at the
    same two moments.
  - **A word misspelt while the folder is up is not kept as typed.** The folder goes on with its
    source; once the daemon has read the file again (any write of `config.toml` does), the next
    bring-up sees the record differ from the folder and writes the folder's real word over the
    typo (`come_up`'s `remember`). "Kept as typed" holds only for the folder that is refused.
  - **The folder is held, with or without interception**, so a second registration is refused
    `AlreadyRegistered` and a Forget takes it away: through the helper for one recorded with
    interception, without it for one recorded without.
  - **What a held folder shows is a guess, used by the Forget alone.** One recorded with
    interception reads `onedrive` in `Source`, and its Forget takes off what a OneDrive folder
    carries (the read-only lock, the tree store, the Baloo exclusion `config.toml` records),
    whichever word was meant. For a folder that is in truth local this is not nothing: taking off
    the lock (`folder/disk.rs` `unlock_tree`) sets every regular file in the folder to 0644 and
    every directory to 0755, the user's own among them, so a 0600 file becomes readable by all and
    executable bits go. Nothing is removed or emptied. One recorded without interception reads
    `local`, and its Forget changes nothing in it: a folder that in truth shows OneDrive without
    interception (left so by a daemon from before HS2) keeps its read-only lock and its tree store
    then, until it is registered again.
  - **A mistyped OneDrive folder with changes waiting to be uploaded** can be neither forgotten
    nor removed with its account: the changes are counted in the store on disk
    (`sync/outbox.rs` `changes_in_store`), and both answer `PendingUploads`. What that
    refusal advises cannot work here: the folder never comes up, and a forced switch to
    read-only drops nothing, because the store is not open. Only correcting the word and
    starting konedrive again helps.
  - **What the commands say meanwhile** names the word: the outbox commands, `Pause` and `Refresh`
    are refused `NotUp` with what `LastError` says.

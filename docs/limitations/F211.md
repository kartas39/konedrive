- **F211. A folder whose `source` in `config.toml` is neither word is held, not repaired**
  (`sync/mod.rs` `Persisted::unread_source`, `sync/registration.rs` `bind` and `persisted_root`,
  `sync/resume.rs` `hold`; quality finding `SY6`) — `source` in `[accounts.root]` is `"onedrive"`
  or `"local"`; only a hand edit produces another value (`"OneDrive"`). The daemon does not guess
  which was meant: the folder is not brought up, `RootState` reads `error`, `LastError` names the
  value, and `config.toml` keeps it as typed. What follows:
  - The user corrects the word and starts the daemon again, or forgets the folder and adds it
    again. Nothing in the window or in `konedrivectl` corrects the word.
  - A folder recorded with interception is held, so its Forget reaches the helper. Held, it reads
    `onedrive` in `RootSource`, and its Forget takes off what a OneDrive folder carries (the
    read-only lock, the tree store, the Baloo exclusion `config.toml` records), whichever word
    was meant; for a local folder there is nothing of these to take off.
  - A folder recorded without interception is not held: its Forget answers that there is no
    folder, as for any such folder whose bring-up failed. The word is corrected by hand.

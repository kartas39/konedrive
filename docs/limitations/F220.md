- **F220. A OneDrive item dated before 1970 shows 1970-01-01 locally** (quality finding `FS1`).
  LIMIT (chosen), *measured* (`remote::materialize::tests::an_item_dated_before_1970_gets_a_placeholder_dated_1970`),
  open.
  `placeholder::set_mtime` takes a time before 1970 since `FS1` was fixed, and
  `PopulateFromDirectory` (the local test source) gives a placeholder its source file's own
  time. The daemon still cuts a OneDrive item's time to 1970 before it sets it, in three
  places: `remote/materialize/file.rs` `cloud_time`, `hydration/graph_source.rs` `mtime_of`
  and `local/examine/found.rs` (the base's time put back). They were left as they are: dropping
  them changes the date the user sees for such a file, and the three have to go together with
  what compares a file's time with the cloud's.
  - **No test makes `futimens` itself fail in a fill.** `commit` (`hydration/source/fill.rs`)
    goes on when the source's time cannot be set, and the stamp records the time the file
    has. Its test (`an_mtime_the_filesystem_cannot_hold_still_hydrates_the_file`) uses the one
    time `set_mtime` still refuses on its own, 2^63 seconds before 1970; nothing on the host
    makes `futimens` fail on a file the daemon has open for writing.
